# Investigating the 0.3 correction regression

The earlier 0.3 workflow produced more unwanted edits than 0.2. Inspection found
fragile partial replacements, changes to technical meaning, and work outside the
mannerism task. Controlled reruns did not establish a consistent disadvantage from
the added rule, candidate format or hints. This report preserves that distinction.

## What caused the observed failures

All 107 applied 0.3 edits were inspected against the frozen correction review. Of the
33 edits flagged as unnecessary, damaging or grammatically worse, only two overlapped
the added guided-tour rule. Twenty-one were outside every lexical cue. Five flagged
operations also appeared unchanged in the corresponding 0.2 output.

Full source context was identical in all 46 called 0.2/0.3 file pairs. The original
skill and output schema were shared. Candidate representation changed, but missing
source context cannot explain the version difference.

Examples of failure mechanisms:

- Replacing a sentence prefix left a noun phrase or an infinitive without its main
  clause. Other patches left doubled articles, repeated wording or broken joins.
- Removing scientific qualifications changed the claim. Absence of supporting
  evidence in an excerpt did not establish that the original claim was false.
- Mathematical and API repairs exceeded the style task. Some might be correct
  repairs; they still should not be applied by this mannerism pass.
- Deleting a broad recap also removed useful qualifications or actions.
- Replacing a trigger word with a synonym sometimes retained the same overclaim.

Eight exposed failure documents were then run through four profiles, with both Luna
and Haiku: legacy 0.2 payload; native 0.3 with the original 30 rules; that profile
without hints; and all 31 rules without hints. Source, old skill, schema and validator
stayed fixed. All 64 calls and all 49 distinct changed copies were covered.

There was no uniform winner across providers. On four documents the last two profiles
had identical model inputs: all eight provider/document repeat pairs generated different
corrected copies, and one pair changed its unwanted-edit verdict. The extra rule or
hints therefore cannot be assigned the aggregate regression from this experiment.

## Repairs and their limits

The companion skill now requires checking the composed sentence after all patches,
preserving technical qualifications and voice, expanding cue boundaries when grammar
requires it, and leaving factual repairs outside this pass. The guide is embedded in
the native CI readout and available through `tics instructions`.

A matched four-document skill-only check retained the old payload, schema and validator.
It avoided scientific qualifier deletion in one file for both providers, but its overall
result was mixed: Luna's unwanted-edit files stayed at two and grammar regressions rose
from one to two; Haiku's unwanted-edit files fell from two to one, with no grammar
regression. Guidance alone is not a demonstrated fix for patch composition.

The comparison's apply helper now preserves delimited math and rejects a small set of
introduced article/punctuation joins, risky imperative-to-infinitive conversions and exact
phrase echoes. It rejects uncertain operations; it does not parse general English or
validate factual claims. Retrospective replay blocks nine of the 33 flagged operations
and none of the 74 nonflagged operations. Twenty-four flagged operations survive. This
is exposed-development evidence, not an independent accuracy estimate.

The native Markdown review scanner also masks dollar-delimited math. Other math notation
and TXT remain visible to the scanner and require downstream preservation. Legacy scans
retain their existing behavior. Tics itself produces candidates and does not apply edits;
the comparison's apply helper is a separate component.

## Expanded comparison protocol

The expanded set contains 64 full files and 32,024 words: the original 32 regression
files plus 32 new, metadata-selected files from approved public sources. References were
frozen before model outputs. Its 696 blocks contain 20 positive, 1,589 acceptable and
1,175 uncertain category judgments. These are native model reviews, not human gold.
Fresh files add no positive empty-framing or contrast cells; those categories remain
poorly measured. Eight short authored mechanism cases are evaluated separately.

Direct review, 0.2 gating and 0.3 gating use the same revised guide, correction-only schema,
four-file batch policy and apply guard. Models receive complete source once, a compact
paragraph index and optional candidate cues. Exact native geometry stays local. This
tests a compact adapter around the tool; it does not establish raw CLI-pipe accuracy.

Gates leave zero-candidate files unchanged and unreviewed. They remain in every denominator.
Usage counts each request attempt once, including any format retry; cached input is part
of total input, and reasoning is a subset of output. Phase wall includes scanning,
requests and application. Separate retries are reported as composite active time.

The schema and batching differ from the earlier instrumented comparison. Cross-experiment
cost changes cannot be attributed solely to the skill. This is a matched single-pass patch
workflow with a fixed batch policy, not a comparison against every possible LLM editor or
batch size. Execution order and cache state limit general timing claims.

## Expanded results

All 147 distinct changed copies (153 condition/file occurrences) were reviewed with
provider and condition hidden. There were 403 canonical reviewed change units and
415 actually applied operations. Every file remains in the totals.

| Model / workflow | Known issues resolved /20 | Files with unwanted/damaging edits /64 | Grammar regressions /64 | Time including retry, seconds |
|---|---:|---:|---:|---:|

| Luna / Direct + skill | 2 | 7 | 1 | 48.73 |
| Luna / 0.2 gate + skill | 1 | 6 | 2 | 49.38 |
| Luna / 0.3 gate + skill | 2 | 5 | 4 | 57.52 |
| Haiku / Direct + skill | 8 | 3 | 0 | 169.73 |
| Haiku / 0.2 gate + skill | 7 | 6 | 0 | 227.76 |
| Haiku / 0.3 gate + skill | 5 | 6 | 0 | 252.92 |

Luna 0.3 resolved the same two known issues as direct review and fewer files received
identified unwanted edits, but grammar regressions increased from one to four. Haiku
0.3 resolved five issues versus eight, with six affected files versus three. Neither
preserved quality while improving efficiency. Uncertain outcomes remain unresolved.

| Model / workflow | Requests including retries | Skipped files /64 | Input tokens | Output tokens |
|---|---:|---:|---:|---:|
| Luna / Direct + skill | 16 | 0 | 305,491 | 12,643 |
| Luna / 0.2 gate + skill | 14 | 15 | 274,482 | 11,905 |
| Luna / 0.3 gate + skill | 14 | 15 | 277,535 | 11,170 |
| Haiku / Direct + skill | 16 | 0 | 232,467 | 159,499 |
| Haiku / 0.2 gate + skill | 13 | 15 | 201,714 | 200,367 |
| Haiku / 0.3 gate + skill | 13 | 15 | 202,315 | 211,987 |

Both gates skipped the same 15 files, including two files containing known issues.
Native scanning itself took about 0.8 seconds per 64-file gate phase. The delays were
in model review and retries. The 0.3 Luna workflow reduced combined input/output tokens
by about 9% versus direct review, while taking about 18% longer after its format retry.
Haiku 0.3 used about 6% more combined tokens and took about 49% longer. Cache state and
one run per condition prevent a universal latency ranking.

The fresh 32-file slice also fails to establish a win: Luna 0.3 and direct each resolve
one of ten known issues, with three affected files each, but grammar regressions are
three versus one. Haiku 0.3 resolves two versus three, with four affected files versus
two. The older regression slice therefore cannot stand in for independent improvement.

The four remaining Luna 0.3 grammar failures include two new lowercase paragraph starts
and two duplicated introductions. One output reads “Prime numbers Prime numbers serve”.
The guard did not catch these different constructions. Instructions to reread composed
sentences are insufficient protection, and more heuristic coverage alone would not
establish semantic reliability.

The separate authored cases show a narrow coverage benefit: 0.3 admits one additional
positive file over 0.2. Luna resolves two of four issues with 0.3 versus zero with 0.2;
Haiku resolves one with either gate versus three directly. These eight short authored
cases do not overturn the natural/regression set.

A separate four-document development check removed required cue-audit exports while
holding source, skill, candidates and guard fixed. It was mixed: Luna became slower
and introduced more unwanted edits; Haiku changed little in latency and avoided one
unwanted edit. This does not establish audit export as the main cause or justify
replacing the full-set result with a preferred pilot.

## Verdict and saved state

**0.3 remains an unreleased review candidate, with no demonstrated correction-efficiency
advantage over direct LLM review.** Exact source delivery, hotspot summaries and embedded
instructions are useful infrastructure; their presence does not establish better edits.
The installed binary remains 0.2.0. No merge, release, commit or install was performed.

The local fixes are the precision guide and Markdown math masking. The separate experiment
also uses the strengthened apply guard; it is not part of a native automatic editor.
All 110 repository tests, strict Clippy and formatting checks pass; the crate is packaged
and compilation-verified. Future grammar repairs need a new prospective test, preserving
this failed comparison and the remaining cases rather than claiming the guard solved them.
